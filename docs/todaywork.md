📄 [기획서] 유령 재고 방지 및 유연한 재고 점검 시스템

1. 기획 배경 및 목적
   문제점: 현장 직원은 눈에 보이는 실물 위주로 검색하여 재고를 조사하므로, 전산에만 존재하고 현장에는 없는 '유령 재고'가 지속적으로 누적됨.

해결 과제: 사내용 PWA의 가벼움을 유지하면서 현장 직원의 추가적인 학습이나 업무 피로도 없이 유령 재고를 100% 식별해 내는 것. 현장의 다양한 변수(요일 변경 등)에 대응할 수 있는 유연성 확보.

핵심 전략: 전산 데이터를 시각화하여 현장 직원이 '지워나가는(소거법)' 방식의 UI 도입 및 완벽한 이력 추적(Audit Trail) 구현.

2. 핵심 사용자 시나리오 (Workflow)
   본 시스템은 관리자가 설정한 재고 점검 모드 활성화 시에만 특별한 UI로 작동하며, 비활성 시에는 기존의 깔끔한 기본 UI를 유지합니다.

현장 직원 (수량 확인 및 소거):

점검 모드가 켜진 날 앱을 열면, 이번 점검 회차에서 아직 확인되지 않은 상품들의 테두리가 **주황색(미점검)**으로 표시됨.

현장 선반을 보며 상품을 검색 후 상세 페이지 진입.

실물 수량과 앱 수량이 다르면 [조정] 처리, 같으면 신설된 [✅ 수량 일치] 버튼 클릭.

클릭 시 즉각적인 피드백과 함께 상품 목록 페이지에서 해당 상품의 카드 테두리가 **초록색(확인 완료)**으로 변경됨.

수시로 [재고 점검 잔여 목록]필터 기능을 통해 자신이 놓친 주황색 카드가 있는지 스스로 크로스체크함.

3. 기능 및 UI/UX 상세 요건
   3.1. 관리자 설정 (유연성 확보)

메뉴 위치: 전체 햄버거 메뉴 內 [설정] 페이지 하단에 '재고 점검 모드 관리' 섹션 신설.

세부 기능:

정기 점검 요일 설정: 다중 선택 가능 (예: 매주 금요일 자동 켜짐).

수동 오버라이드 토글: 설정된 요일이 아니더라도 강제로 점검 모드를 켜고 끌 수 있는 스위치 (이슈 발생 시 연기 처리 및 기능 테스트용).

3.2. 상품 목록 페이지 UI 및 동기화 정책

상태별 컬러 피드백 (점검 모드 활성화 시):

미점검 상태: 주황색 테두리(border-warning)

확인 완료 상태: 초록색 테두리(border-success)

비점검 모드(평상시): 기존 기본 테두리 유지.

[재고 점검 잔여 목록] 신설:

접근성: 관리자뿐만 아니라 실무자도 상시 접근 가능하도록 상단 햄버거 아이콘의 메뉴에 신설.

기능: 점검 모드가 켜져 있을 때, 상품 목록 페이지에서 아직 '미점검(주황색)' 상태인 상품만 모아서 보여주어 자체 크로스체크 지원.

멀티 작업자 동기화 정책 (Concurrency):

로컬 즉시 업데이트 (Optimistic UI): 버튼 클릭 후 리스트 복귀 시 서버 응답을 기다리지 않고 해당 아이템 상태를 즉시 초록색으로 렌더링하여 작업 딜레이 방지.

서버 재조회 동기화: 잔여 목록 진입 시 또는 화면 탭 이동 시 서버 기준으로 최신 데이터를 재조회하여 타 작업자의 점검 내역을 동기화.

**가능하면 Supabase Realtime 같은 실시간 반영**

3.3. 상품 상세 페이지 기능 및 마이크로 인터랙션

[✅ 수량 일치] 버튼 신설:

기존 [조정] 버튼을 반으로 분할하여 우측에 나란히 배치 (그리드 유지). 안정감을 주는 색상으로 텍스트/테두리 적용.

액션 이펙트 (UX 최적화):

시각: 터치 시 버튼 배경이 알맞은 색으로 채워지며 텍스트가 확인 완료로 1초간 변경.

"재고가 확인되었습니다." 토스트 메시지 출력.

3.4. 데이터 이력 관리 (Audit Trail)

[최근 입출고 이력] 업데이트:

수량의 변동이 없더라도 [수량 일치] 버튼 클릭 시 해당 섹션에 이력을 반드시 남김.

표기 형태: 입고(초록), 출고(빨강)와 구분되는 중립적인 색상(예: 파란색/회색 선) 사용.

텍스트 예시: "재고 확인 (변동 없음) / 현재 수량 : 8"

4. 데이터베이스 및 백엔드 처리 규칙 (중요)
   점검 회차(Check Run) 도입: inventory_check_runs (id, started_at, ended_at, mode_source, created_by) 테이블을 신설하여, 점검 모드가 켜질 때마다 고유한 회차(Run) ID를 발급함.

상태 판별 (초록색 전환) 기준: 단순 날짜 비교(last_inventory_checked_at)가 아닌, 현재 활성화된 점검 회차(Active Run) 내에 해당 상품의 확인 이력(History)이 존재하는지로 판단하여 '가짜 확인'을 원천 방지함.

트리거 조건 및 데이터 기록: \* 오직 수량 변화 수반 또는 현장 확인 액션([입고], [출고], [조정], [수량 일치]) 발생 시에만 이력 테이블(History)에 Insert하며, 이때 check_run_id를 함께 기록함.

last_inventory_checked_at 컬럼은 단순 최근 점검일 보조 지표로만 업데이트함.

상태 업데이트 예외 조건: [속성정보 수정]을 통한 단순 정보 변경은 트리거 및 이력 기록에서 배제하여 점검 완료 내역에 포함되지 않도록 함.

5. 기대 효과
   데이터 신뢰성 확보: 유령 재고가 필터링 탭에 자동으로 걸러지며, '점검 회차' 기반의 검증과 모든 확인 내역의 이력 저장을 통해 완벽한 추적(Traceability) 가능.

현장 맞춤형 유연성: 기상 악화나 현장 이슈로 인한 점검 일정 변경에 시스템이 100% 유연하게 대응 가능.
